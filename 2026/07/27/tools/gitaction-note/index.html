CI/CD

CI/CD 持续集成和持续部署
continuous integration and continuous deployment

是持续验证变更并保持软件处于一种可以安全、可靠发布的状态
是一种可重复的，确保每次都能执行相同检查的软件发布过程

CI

每次推送代码，自动进行测试，并与其余代码库进行验证

  1. Code Commit
    • 开发者编写代码并推送至仓库
  2. Continuous Integration
    • 更改被自动拉取并融合
  3. Build
    • 安装依赖，编译程序，构建项目
  4. Test
    • 自动化测试确保代码质量
    • 反馈 2. Continuous Integration 阶段

CD

在通过测试后，代码将始终处于随时可以发布的状态，可以随时部署

  1. Package
    • 项目被打包为应用（如 docker image、.jar …）
  2. Deploy to Staging
    • 自动部署到环境中
  3. Deploy to Production
    • 自动部署到生产环境
  4. Monitor
    • 由系统监控应用程序的性能和故障

CI/CD 实践

实践仓库：http-server — 基于 Boost.Asio / Boost.Beast 的 C++ HTTP 服务器

目标文件

文件 说明
.github/workflows/http-server-ci.yml CI 流水线：CMake 构建（Debug + Release 矩阵）、GTest 单元测试 + 集成测试、ccache 编译缓存

技术栈要点

  • 语言：C++17, CMake 3.15+
  • 依赖：Boost 1.83（system, thread, filesystem, log, program_options, json）
  • 测试：Google Test + ctest（57 用例）
  • CI 环境：ubuntu-24.04, actions/checkout@v6, actions/cache@v5 (ccache)
