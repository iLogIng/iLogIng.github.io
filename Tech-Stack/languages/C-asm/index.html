C内联汇编

在 C 语言中，内联汇编通常使用编译器扩展来实现。
最常用的是 GCC 的扩展内联汇编（用于 Linux 内核、xv6、OSTEP 实验等），这里重点汇总它的语法。
MSVC 的内联汇编语法不同（__asm {} 块），简单提及但不展开。

一、GCC 基本内联汇编

  • 编译器直接将字符串中的汇编指令插入生成的汇编文件。
  • 无法与 C 变量交互，通常只用于简单的指令（如 nop、cli、sti）。
  • 通常配合 volatile 防止被优化删除：asm volatile ("nop");

三、常用约束符

约束 含义（x86） 示例
r 通用寄存器 "r"(x)
m 内存操作数 "m"(var)
i 立即整数 "i"(42)
g 寄存器、内存或立即数均可 "g"(x)
a eax/ax/al 寄存器 "a"(val)
b ebx/bx/bl "b"(val)
c ecx/cx/cl "c"(count)
d edx/dx/dl "d"(data)
D edi/di "D"(ptr)
S esi/si "S"(ptr)
=r 只写输出到寄存器 "=r"(out)
+r 可读写寄存器 "+r"(var)
=&r 早期破坏（earlyclobber），输出在输入被用完之前写入 "=&r"(result)

四、常见修饰符

  • = 输出只写。
  • + 操作数可读可写。
  • & 表示操作数在指令执行前就被修改（早期破坏），避免与输入分配同一寄存器。
  • % 在模板中引用操作数，如 %0；如果与寄存器名连用，如 %%eax。
  • volatile：放在 asm 后，禁止编译器删除或移动该汇编块（即使它看起来没有输出）。
    • 有输出操作数时一般不需要，但通常加上以防优化。

七、MSVC 内联汇编

  • 只能用于 32 位 x86，不支持 x64，不支持 ARM。
  • 不支持 GCC 扩展的约束语法，直接访问变量名，编译器自动分配。

八、关键注意事项

  1. 破坏列表不能省略：如果你修改了寄存器或内存，必须告知编译器，否则可能导致难以调试的运行时错误。
  2. 避免直接硬编码寄存器：尽量使用约束让编译器分配，除非有特殊要求（如系统调用使用特定寄存器）。
  3. volatile 和 "memory"：当汇编指令有副作用且无输出操作数时，必须加 volatile；如果修改了内存位置，要加 "memory"。
  4. 内联汇编中的 C 标签：支持跳转到 C 标签（asm goto），用于内核中的某些错误处理，但较复杂。
  5. 可移植性：内联汇编与架构强相关，因此通常用 #ifdef 包裹不同架构的实现。
