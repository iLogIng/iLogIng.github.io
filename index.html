About Web API

关于网页API

Canvas2D

可以通过 <canvas>网页元素，使用 javascript 脚本来绘制 HTML 元素，进行2D图形绘制

栅格

canvas grid

通常来说网格中的一个单元相当于 canvas 元素中的一像素。栅格的起点为左上角（坐标为（0,0））。
所有元素的位置都 相对于原点定位 。距离左边 X轴 x像素，距离上边 Y轴 y像素。

绘制路径

图形的基本元素是路径。路径是通过不同 颜色 和 宽度 的 线段 或 曲线 相连形成的不同形状的 点 的集合。
一个路径，甚至一个子路径，都是 闭合的 。使用路径绘制图形需要一些额外的步骤。

  1. 首先，你需要创建路径起始点。
  2. 然后你使用画图命令去画出路径。
  3. 之后你把路径封闭。
  4. 一旦路径生成，你就能通过描边或填充路径区域来渲染图形。

SVG

在网页中由 <svg> 元素标记

可缩放矢量图形 Scalable Vector Graphics，SVG 基于 XML 标记语言，用于描述 二维的矢量图形

作为一个基于文本的开放 Web 标准，SVG 能够优雅而简洁地渲染不同大小的图形，并和 CSS、DOM、JavaScript 和 SMIL 等其他 Web 标准无缝衔接。本质上，SVG 相对于图像，就好比 HTML 相对于文本。

SVG 图像及其相关行为被定义于 XML 文本文件之中，这意味着可以对它们进行搜索、索引、编写脚本以及压缩。此外，这也意味着可以使用任何文本编辑器和绘图软件来创建和编辑它们。

和传统的 点阵 图像模式（如 JPEG 和 PNG）不同的是，SVG 格式提供的是 矢量图 ，这意味着它的图像 能够被无限放大而不失真或降低质量 ，并且可以方便地修改内容，无需图形编辑器。通过使用合适的库进行配合，SVG 文件甚至可以随时进行本地化。

WebGL

可以在 <canvas> 元素内使用

WebGL（Web 图形库）是一种可在任何兼容的 Web 浏览器中无需使用插件即可渲染高性能交互式 3D 和 2D 图形的 JavaScript API。
WebGL 通过引入一个与 OpenGL ES 2.0 高度一致的 API 来做到这一点，该 API 可以在 HTML 元素中使用。
这种一致性使 API 可以利用用户设备提供的硬件图形加速。

所有现代浏览器都支持 WebGL ，用户的设备也必须支持这些特性。

WebGL 2 API 引入了对 OpenGL ES 3.0 特性集的广泛支持；它通过 WebGL2RenderingContext 接口提供。

<canvas> 元素也被 Canvas API 用于在网页上进行 2D 图形处理。

Web Audio

处理过程可以视为一张有向无环图，图中的各个节点作为处理过程

Web Audio API 使用户可以在 音频上下文 AudioContext 中进行音频操作，具有模块化路由的特点。
在音频节点上进行基础的音频操作，它们连接在一起构成音频路由图。
即使在单个上下文中也支持多源，尽管这些音频源具有多种不同类型通道布局。
这种模块化设计提供了灵活创建 动态效果 的 复合音频 的方法。

音频节点通过它们的输入输出相互连接，形成一个链或者一个简单的网。
一般来说，这个链或网起始于一个或多个音频源。音频源可以提供以数组形式存储的一个片段一个片段的音频采样数据。

这些节点的输出可以连接到其他节点的输入上，然后新节点可以对接收到的采样数据再进行其他的处理，再形成一个结果流。

一个简单而典型的 web audio 流程如下：

  1. 创建音频上下文
  2. 在音频上下文里创建源 — 例如 <audio>, 振荡器，流
  3. 创建效果节点，例如混响、双二阶滤波器、平移、压缩
  4. 为音频选择一个目的地，例如你的系统扬声器
  5. 连接源到效果器，对目的地进行效果输出

使用这个 API，时间可以被非常精确地控制，几乎没有延迟，这样开发人员可以准确地响应事件，
并且可以针对采样数据进行编程，甚至是较高的采样率。这样，鼓点和节拍是准确无误的。

Web Audio API 也使我们能够控制音频的空间化。
在基于 源 - 侦听器 模型的系统中，它允许控制 平移模型 和处理 距离引起的衰减 或 移动源（移动侦听）引起的多普勒效应。

  • Canvas2D 是 立即模式 ：每帧 clearRect -> 重新发路径/填充命令 -> 浏览器负责变成像素。
    这和 SDL3 的 SDL_RenderClear + 逐帧提交绘制命令是同一个心智模型。
  • SVG / DOM / CSS 是 保留模式 ：你维护树结构，浏览器维护状态并负责渲染。
  • 立即模式：每帧重新描述 输出帧图像，系统不保留跨帧的绘制对象；绘制命令发出后即被消费，下一帧从空白开始
  • 保留模式：开发者维护一个跨帧持久的对象图（场景/树），系统保留并负责在 需要时渲染 ；通过更改该对象图以间接影响画面，而非逐帧重发绘制指令

判断标准只有一个：是否存在一个由系统维护、跨帧持久、你通过修改它来驱动渲染的对象图

立即/保留 不是二元标签，它取决于你看的是哪一层。同一个技术可以在命令层是立即的，在资源层是保留的。

层面 立即模式 保留模式
绘制命令层 每帧重新发 draw 调用；命令发完即弃 系统根据对象图自行决定何时、如何发命令
资源层（几何、纹理、缓冲区） 几乎不存在纯立即的资源管理 VBO、纹理、Image 对象跨帧保留，这是常态
对象图/场景层 没有持久对象图 有：DOM 树、SVG 树、Three.js Scene

一些关于神经网络的理解

一些基于深度学习前馈网络的理解

目标函数（Objective Function） 是在整个训练过程中真正想要最小化（或最大化）的终极目标。
损失函数（Loss Function） 是衡量预测错误的基础度量。
目标函数 = 损失函数 + 正则化项。
工程实践上通常混合使用

残差连接 和 LayerNorm、Multi-Head Attention

在深度神经网络中

  • 神经网络形状
    • 输入矩阵是 特征 是 数据的张量表示
    • 输出是 模型对标签的 预测值
    • 计算的损失函数(loss)是针对网络最后的输出，网络中各个神经元根据该loss通过链式法则进行梯度下降（总趋势是向loss最小的方向下降，所以每个神经元的方向可能不同）
    • 每个神经元都是数据的一种表示 x
    • 神经网络中的各个边代表的是 权重(weight) w
    • 神经网络中，每个神经元的 偏置(bias) b 对该神经元产生的所有加权特征进行平移，以提供更精确的拟合
    • 神经网络中，每个神经元的输出 a 都是标量
    • 每层的 wx + b = y 得到的都是该层神经元的线性输出 z=y ，通过激活函数得到该层的输出，即下一层的 x=a=activation(z)（激活后的z）
  • 激活函数 是在神经元输出前将线性输入非线性化的一种方式
    • 激活函数就是将神经元内部线性变换得到的线性输出（wx + b = y = z）通过非线性变换激活为神经元输出的一种函数，得到下一层的 x

ffprobe

是一个非常强大的 多媒体分析工具 ，可以从媒体文件或者媒体流中获得用户想要了解的 媒体信息 ，
比如音频的格式、视频的宽高、媒体文件的时长等参数信息等。
它除了用于分析媒体容器中音频的 编码格式、采样率、通道数目 ，以及视频的 编码格式、宽高等 以外，
还用于分析媒体文件中媒体的 总时长、复合码率等 信息。
使用ffprobe还可以深入分析媒体文件中 每个压缩媒体包的长度、包的类型、包对应的帧的信息等

Multi Media Basics

Color & Picture

现实生活中的物体靠 吸收 与 反射 光展现其颜色

常用的有两种色彩空间

  • RGB
    • R Red 红
    • G Green 绿
    • B Blue 蓝
    • 是 加色系统 ，用于 发光体
  • CMYK
    • C Cvan 青
    • M Magenta 洋红
    • Y Yellow 黄
    • K blacK 黑
    • 是 减色系统 ，用于 印刷制品 （现实生活中难以获取纯色，为了与期望的颜色接近，需要在颜色中加入黑色）

在数字显示世界中，处理音视频，一般使用 RGB 色彩空间

计算机中，图像的存储一般使用 位图(Bitmap) ，其中每个点称为 像素(Pixel)
对于 RGB 色彩空间，每个颜色分量称为一个 通道(Channel)
通常，每个像素的每种颜色分量用 1字节(1Byte = 8bit) 表示，存储一个像素的色彩就需要 24位
也称为 24位真彩色 ，一共可表示 2^24 种颜色
为了描述 透明 的图像，在每个像素上再增加一个表示 透明度 的分量，称为 Alpha通道
表示 2^8 种透明度，产生 RGBA 色彩空间，一个像素就需要 4Byte 的空间进行存储，正好可以通过 32位 整数表示
由此，通常使用整数来对图像进行计算

由于计算机在不同架构下其字节序也可能不同，产生数据存储的 大小端* 问题
因此出现了多种不同的存储方式 (RGBA ABGR BGRA ARGB 等)

对于 灰度图 一般使用1Byte进行存储
对于 单色图 一般使用1bit进行存储
